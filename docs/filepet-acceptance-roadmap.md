# FilePet 下一阶段优化与验收计划

范围：原生 macOS FilePetShell + 本地 Python 分类核心。按 P0 → P1 → P2 → P3 验收，不重做外观框架、不上传文件、不修改冻结的花朵 v2 原素材。各阶段通过后再合并 Draft PR；每项失败需保留可复现输入与 CI/本地截图或录屏。

## P0 · 菜单简化、花朵可见数量（本次已实现，待用户本地验收）

- 状态菜单仅保留：连接简况、导入文件、DDL 任务列表、（非零时）待确认、归档目录、显示花朵数量 1/2/3、更多操作、退出。
- 更多操作保留：自动识别图片 DDL 开关、显示葡萄藤、最近分类结果、撤销上次采摘、重新连接引擎、已配置时停止自动移动归档。
- 可见花朵设置独立持久化为 `filepet.shell.garden.visibleLimit.v1`；旧用户默认 1 朵，有效值始终限制为 1–3。
- 先显示即将截止的未完成 DDL，余者排队，逾期 DDL 不被删除且最多占一个空位；切换 1→2→3→1 只增加/收起必要面板，不重建保留中的花朵面板。调整只影响呈现，不修改 ID、完成状态、来源或队列记录。

**验收：** 准备 5 条不同截止日期任务。分别选择 1、2、3 朵，确认常驻数量恰为 1、2、3，队列分别为 4、3、2；重启后保持选择值，改变系统时间后仍优先显示临近任务。让一个任务逾期，确认它仍在任务列表；完成当前可见花后下一项补位，撤销后恢复。验证菜单无需滚动即可看到主要功能，拖入文件、透明区域点击穿透与多屏位置不退化。

## P1 · OCR 自动化与任务语义（下一轮核心）

- 用真实截图建立**至少 30 张**版本化脱敏样本：学习平台、群消息、同一作业的不同裁切、带 AM/PM 的日程表、多作业时间区间、发布日期干扰、空白截图。
- 后端只做一次 OCR；分类和 DDL 分支共享文本，课程/作业/截止时间应来自同一内容区域；不能把文件名、附件名或发布时间误作截止。
- 让完整有效且明确的 DDL 默认自动生成花朵；年份推断、OCR 严重缺损、冲突日期才进入静默待确认；提升理解力的同时保留可编辑/撤销操作。
- 同一截图重复投喂、改名、等价局部裁切，避免重复葡萄与 DDL；不合并两门课的同名作业。

**验收：** 示例截图“计算机网络 · 第四章作业”自动产生一条 2026-11-08 23:59 的花，不出现人工弹窗。建议阶段目标：30 张样本中的明确 DDL 自动处理率 ≥90%，关键截止时间错误率 ≤5%（仅作验收目标，须以真实样本统计，不是现有成绩）；人工复核例子也能在列表编辑/确认。运行 `cd backend && python -m pytest -q`，不把跳过的集成测试算作通过。

### P1 实施进度（2026-11-02）

- 已修复 Swift 外观中“相同作业的不同截图裁切生成重复葡萄”的问题：以 `类别 ID + 核心 semantic_key` 识别已经计数的作业，使用新独立 UserDefaults 键 `filepet.shell.inventory.semanticGrapes.v1` 持久化；同一张图新增不同作业时仍应增加葡萄；已有完成记录和花朵仍由稳定 DDL ID/语义键去重。类别不同的内容不会互相吞并。
- Python 增加 **15 个脱敏 OCR 文本场景 + 1 个跨裁切语义关联测试**（`backend/tests/test_ocr_acceptance_matrix.py`），涵盖用户截图文本、英文 PM、星期、三个作业、多课程/发布日期干扰、无效日期、无截止语义和推断年份。它们是有标注的 **OCR 文本转录/模拟样例**，不等于真实图片 OCR 测试。
- 当前后端 CI 为 **149 passed、1 warning**（[41468897413](https://github.com/m1kezhuu/slime-file-classifier/actions/runs/41468897413)）；外观 CI **124 个 XCTest 已调度且无记录失败**（[41468660303](https://github.com/yunleeeee/appearance/actions/runs/41468660303)）。
- **尚未达标：** 需要用户授权并在本机脱敏收集至少 30 张真实截图，记录 OCR 原文、真值标签、自动接纳/误报/漏报和时间错误；未取得之前不报告 ≥90% 自动处理率或 ≤5% 时间错误率为已实现的成绩。

## P2 · 原图唯一性与归档安全

- 选择分类保存目录后，成功分类的图片只保留归档位置的一份；对系统生成名称使用真实作业名，人工命名文件尊重原名。
- 目标文件先写临时文件、验证 SHA-256、正式落盘再删除源路径，禁止覆盖同名异内容文件；失败不删除原文件。移动后更新任务、待确认记录以及“查看来源”链接。
- 完善失败恢复/权限处理：只读目录、路径失效、同盘与跨盘、拖入符号链接、重启、重复投喂及大文件。

**验收：** 选择临时测试目录而非真实重要文件，投喂同名、重名不同内容和跨盘样本，断言没有丢失、没有损坏、来源可以打开。未选择保存目录时绝不移动。失败时原件完好，重新操作不会出现无限重复副本；明确提醒用户此功能会改变原路径。

### P2 本轮加固（2026-11-02）

归档过程已增加**删除原件前再次计算源文件 SHA-256** 的保护：如果其他进程在目标文件落盘后修改了源文件，不应继续无条件删除修改后的版本。SHA-256 不替代文件系统级原子事务；尤其在源文件正被别的应用写入时仍存在极小的并发窗口。真机验收应优先使用副本或临时数据验证同盘/跨盘、文件锁、存储空间不足和移动失败后的恢复。

## P3 · 花朵美感、性能和桌面稳定性

- 延续已确认的像素素材、茎叶锚点与自然风摆。保证 1 朵直立且舒展，2–3 朵之间高低和方向有微妙差异，避免机械同步；数量变化及 DDL 阶段变化无闪烁。
- 六阶段严格按真实截止时间，含日历日未注明时间、睡眠唤醒、时钟/时区变更及逾期未完成。Reduce Motion 下停止持续摆动但保持视觉可辨。
- 常驻空闲时停止不必要的绘制与图片解码；验证多显示器、全屏、透明区域鼠标穿透和拖放功能。

**验收：** 提供 1/2/3 朵常驻截图、六阶段截图和风摆/数量切换录屏。长时间（建议至少 8 小时）在真实 Mac 上观测空闲 CPU/内存和窗口数量，与改动前记录对比；以“不持续全窗口 25ms 重绘、无明显 CPU/内存增长”为阻断条件。运行 `cd frontend/macos && swift test` 以及 macOS CI；真实截图和录屏必须来自运行中的 App 而非静态设计图。

### P3 新增：双击采摘与原创剑光碎瓣动画（2026-11-07）

- **交互：** AppKit 花朵仅接受在非透明像素上的 **双击**（移动距离小于 6pt）触发采摘；单击只查看悬停详情，拖入文件不受影响。双击后没有 NSAlert、没有二次确认。误操作继续通过“更多操作 → 撤销上次采摘”恢复本地任务。
- **视觉节奏：** 约 1.12 秒原创紫青交错高速剑光；0.31 秒后将复用 v2 花头原始像素贴图的 12 个裁切碎片沿不同方向散开，重力下坠，在桌面底线形成微弱火花后消失。花茎、叶片同期逐渐收束；并非逾期自然凋零动画，且不触碰封存的原始 PNG。演出期间花位保留，动画完成后才写入完成状态并补位下一朵。
- **性能及无障碍：** 仅在采摘的短暂持续时间启用 24fps 定时重绘；空闲时不启动特效。Reduce Motion 将效果缩短为约 0.16 秒静态弱光消散，没有快速剑光扫动或飞散碎片。采摘期间透明花朵窗口拒绝新的点击，避免重复完成和干扰桌面。
- **自动验收：** `HarvestSlashEffectTests` 校验单击不采摘、双击生效、拖动和透明区域不触发、重复触发被忽略、时序阶段、减少动态效果、末帧不留残像；`DeadlineVisualProofTests` 额外生成 `harvest-sword-frames/` 和由 CI ffmpeg 编码的 `harvest-sword.mp4`。这些属于原生 AppKit 离屏渲染证明，不等于真实桌面录屏。
- **尚需本地验收：** 在 Mac 真机分别切换常驻 1/2/3 朵、双击第一朵，看交错剑光及碎片下落是否自然、下一朵是否在约 1.1 秒后平滑补位、撤销采摘是否恢复。检查屏幕边缘、全屏、多屏定位、Reduce Motion 和高 DPI 下的视觉完整性；用户可根据真实效果调整时长和亮度。

## 合并门槛

1. 两个仓库的功能分支和 PR 都保持 Draft，直到各自测试通过并且至少一轮真实 Mac 拖入、文件移动与花朵展示验收完成；不直接强推 `main`。
2. 提供实际执行的命令、CI 链接、通过/失败/跳过数量；没有运行的测试明确标为“未验证”。
3. 保持 `/classify`、`/jobs`、`/jobs/{job_id}`、既有 UserDefaults 和花朵资源兼容；后端 OCR/分类协议可复用，Windows 外观单独实现。
4. 优先修复阻断性错误（误删除/丢失文件、重复任务、错误时间）后，再进行装饰性视觉微调。
