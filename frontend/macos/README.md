# 葡萄藤 · 切花测试版（macOS）

外观唯一维护在 `appearance`。分类、正文提取和 DDL 提取由 Python 核心提供。可以在 App 中指定分类归档目录，归档在用户明确选择目录后执行校验式移动，原位置文件在目标落盘且验证成功后才删除。

## 打开 App

本分支基于稳定 `main`，实验双击切花特效。11 月 8 日进一步把切割目标扩展为**覆盖整株植物的长方形**：花冠、所有叶片、整段茎干、根部与脚边草地统一冻结成带透明像素的快照，两记主斩配合低强度残影覆盖花冠至根部，短暂停顿后由一记纵贯整株的白热刀锋造成真实切口；局部短暂黑白反相冲击帧之后，花朵先按刀锋路径分成两块黑白主体，再裂成错位三角碎片并独立坠落消散（常规约 1.38 秒；「减少动态效果」约 0.16 秒）。特效层不接收鼠标，原花朵的窗口与交互区域不扩张，避免让桌面其他区域变得无法点击；特效结束时也不会闪回完整花朵。安装包使用独立标识 `com.filepet.GrapeShell.VFXTest` 和本地偏好，默认不导入稳定版的葡萄、任务或归档目录；测试前请使用文件副本。单击不完成任务，双击播放切花动画，动画结束后才采摘并补位。进入全屏或隐藏挂件会取消未完成的动画，返回桌面后该任务仍可继续处理。

请先退出正在运行的葡萄藤，再构建或启动测试版；现有构建与开发脚本会阻止同时运行两个版本。

双击 `build/FilePetShellVFXTest.app` 即可。App 会自己启动并连接本机分类核心，终端不需要保持打开。无参数运行 `启动葡萄藤.command` 也会直接打开 App，不再询问文件夹。

自动模式使用当前用户的主目录作为核心可读取范围，仅在主动拖入或选择文件后分析，不扫描目录。macOS 对桌面、文稿、下载等位置的系统权限仍适用。App 为本机非 App Store 构建，不启用会阻止外部 Python 子进程的 App Sandbox；核心仍只绑定本机地址并执行其路径授权检查。

自动服务使用独立空闲端口，不依赖固定的 8765。启动时先等待健康检查，再读取类别；重复连接复用 App 自己的服务，服务退出后会在空闲时自动检查并重新启动，也可从菜单手动重新连接。退出 App 只停止自身服务，不停止外部启动的引擎。

## 2026-11-09 · 电影化剑阵迭代（来自实际录屏评审）

目标：**整株矩形区域内的快速七连斩 → 约 70ms 瞬停 → 一道贯穿花冠到根部的终结斩 → 不规则爆碎 → 地面消散**。录屏显示旧版粗圆头蓝紫光轨类似荧光棒，且碎片整齐分成两列。现已改为两端收尖的剑锋、统一紫晶与银白色高对比度轮廓、普通斩与终结斩的明确大小差异、不遮挡桌面的终结斩交叉余辉（逐帧检查后舍弃像 UI 卡片一样的矩形背景）。

花朵碎片的矩形网格改为偏移的 10×17 三角单元，独立方向和速度，额外细碎晶光从中心爆发，避免齐刷刷的左右两列下落。动效总时长约 1.62 秒，原有 reduce motion 和测试版数据隔离保持不变。

CI 会导出 `harvest-sword-frames` 和 `harvest-sword.mp4`；通过编译和单测并不代表视觉效果自动达标，仍需逐帧和实机确认。

## 历史尝试（已被新版替代）：2026-11-09 · 「月下紫电」配色重构

对照紫电剑光、Stylized Sword Slash 和视觉特效色彩分层参考，取消先前高饱和的紫青粉三色混用，统一为**夜墨紫（#302348）轮廓、紫晶（#8D77DB）刀身、浅鸢尾（#C6B7F3）余辉、银白（#F4F0FF）刀锋、极少量香槟金（#E9C89C）碰撞星屑**。

这一版曾把斩击、终结剑光、切痕、矩形角标、爆闪、落地光环和碎裂晶片改为使用同一套代码颜色常量；现已被下方「墨影·断色」方案替代。金色只在部分爆裂火花出现，不让第二个高饱和颜色抢主视觉。几何、帧时间、碎片物理和缩减动态效果保持原样。色彩请同时在浅色/深色壁纸下验收，以实机观感为准。

## 2026-11-09 · 「墨影·断色」黑白终结斩

根据 21:00 的实机录屏，不再坚持刻晴紫色系。保留此前已验收的整株矩形刀阵、七连斩、短停顿、终结斩、碎片碰地动画，但将配色改成**冷钢银光 + 石墨色剑影**：刀光在浅色桌面上有深轮廓，不使用强饱和紫青荧光。

关键是让褪色成为剧情节奏而不是滤镜：终结斩约 0.61s 命中后，花朵整体在 0.10s 内由彩色变为高对比黑白，0.72s 开始花冠、叶片、茎干、根部一起碎裂。分片使用**预先缓存的黑白整株图**，保持原透明度与像素风质地；最终爆闪、刀影、地面晶光全部只用灰阶颜色（无旧粉紫、黄、蓝）。降低动态效果模式仍保留原来的短淡出，不播放黑白闪烁。

Mac CI 单测校验 RGB 三通道相等、像素 Alpha 不变、褪色开始与结束时机；视觉上重点看终结一刀后是否形成明显而干净的黑白断色。

## 2026-11-12 · 「墨影·绝断」关键帧与真实刀痕升级

为解决旧版连续亮线、缺少命中因果和规则碎片的问题，重排为以下阶段：

- **0–0.29s**：两记主要冷钢银色斩击，夹带仅约四分之一亮度的剑影余波，不再七刀同权重
- **0.29–0.42s**：画面收束并静止，保留少量短暂切痕
- **0.42–0.54s**：终结斩用一条固定刀线贯穿整株，花色在约 100ms 内流失；0.505–0.539s 只在花朵内部使用极短黑白负片冲击，不闪整张桌面
- **0.54–0.73s**：整株使用真实刀线作多边形分割，两块较大的花头、叶、茎、根部黑白影像沿切面缓缓分离；前 35ms 刀痕不位移
- **0.73–1.38s**：二次释放碎片。10×17 不规则格网中的每个候选片会先被**同一条真实刀线裁剪**，继承第一阶段的位移，再以分部位速度运动并碰地消散

该实现不使用新的大面积背景卡片、全桌面负片或外部版权素材。测试包含刀线一致性、分块面积守恒、切割前后无重复/遗漏、负片保留透明度、减少动态效果和双击任务逻辑。

## 2026-11-12 · 录像否决：删除中心「烟花」

用户指出黑白碎裂画面的中心灰色放射线像烟花，破坏了刀光剑影的真实切割感。现从渲染路径中**彻底移除**中心射线 `drawImpactFlash` 和中心放射晶片 `drawBurstDust`，不是调小透明度。画面只保留按真实刀线分离的植物与黑白碎片，地面仅有少量低位刮痕和细尘（23 降为 10）。新增无碎片场景的像素级回归测试，防止装饰性星爆重新出现。

## 从源码构建

需要 macOS 13+、完整 Xcode，以及核心目录中已安装依赖的 `.venv`。当前 App 使用本机安装的 Python 环境，不包含完整的跨机器运行时。

```bash
./build-app.sh
open build/FilePetShellVFXTest.app
```

构建脚本默认使用相邻的 `filepet-engine/`，也可设置 `FILEPET_ENGINE_ROOT`。生成的 App 配置会记住这台机器上的核心路径；启动时的环境变量优先，其次检查记录的位置与相邻目录。缺少核心或环境时，App 会给出具体说明，离线动画仍可用。

## 开发时使用外部核心

需要限制到单独目录、使用样例或指定固定端口时，可以显式运行：

```bash
./run-dev.sh --examples
./run-dev.sh --root "$HOME/Downloads"
./run-dev.sh --root "$HOME/Downloads" --port 8766 --engine-root /绝对路径/filepet-engine
```

`--examples` 授权核心的 `backend/`：普通分类样例位于 `scripts/examples/`，DDL 样例位于 `examples/deadline_notice.txt`。支持 `--engine-only` 只开服务。这种模式需保持终端运行，Ctrl+C 只停止脚本启动的核心。

连接自己启动的核心：

```bash
open build/FilePetShellVFXTest.app --args --engine-url http://127.0.0.1:8765
```

显式 `--engine-url` 不会额外启动自动服务。切换模式前退出已运行的 App，避免 macOS 忽略新启动参数；之后从 Finder 直接打开 App 即恢复自动模式。

## 精简菜单与常驻花朵数量

FilePet 菜单的主要操作为：**导入文件**、**DDL 任务**、**归档位置**、**显示花朵：N 朵**、**更多操作** 和退出；存在待确认事项时会额外显示待确认入口。以前的独立连接/花朵状态行合并为一个简短的连接状态，杰瑞偷葡萄和葡萄架预览不再占据日常菜单。

在 **“显示花朵”子菜单**选择 1、2 或 3 朵（默认 1）。切换立即生效，已存在的花朵窗口尽量复用；剩余任务留在 DDL 列表，按临近截止优先，不删除已逾期记录。设置通过 `filepet.shell.garden.visibleLimit.v1` 存在本地，重启继续生效。**“更多操作”**中可以调整自动图片 DDL、葡萄藤显示、查看最近分类结果、撤销采摘、重新连接引擎以及停止自动归档。

详细后续验收步骤见 [FilePet 验收路线图](../../docs/filepet-acceptance-roadmap.md)，其中将菜单与花朵数量设为 P0，真实 OCR、归档安全和动画表现分别作为后续验收阶段。

## 快捷设置分类文件保存位置

打开 FilePet 菜单 → **“选择分类文件保存位置…”**（应用菜单快捷键 **⌘⇧S**），在 Finder 选择一个总目录。以后投喂文件并成功分类时，会自动将文件**移动**至该目录下的类别子文件夹，例如：

```text
你选择的目录/
  课程与学习/
    第一次作业.pdf
  财务与票据/
    报销单.png
```

此操作是可选的：没有选择目录时，只运行分类、增加葡萄以及检测 DDL，不会写入任何分类输出。菜单中选择 **“停止自动移动归档”** 可随时关闭功能，不改变此前已经复制的文件。文件夹选择只保存在本机 UserDefaults，重新打开 App 仍可使用；分类失败、未确认分类或复制失败都不会触碰原文件；成功归档会移除原路径，只保留归档位置的文件。

同一路径、同样大小和修改时间的文件不会重复移动；不同源文件若重名会依次生成 `报告 (2).pdf`、`报告 (3).pdf`，不覆盖已有文件。归档时先复制到临时文件并核对 SHA-256，再重命名到目标位置，最后删除原位置；DDL 的来源路径会同步更新到新位置。用户稍后手动补充分类型别时，也会尝试移动到已设置的分类目录。移动在后台执行；跨盘归档需要足够的临时空间和系统文件权限，若校验失败原件保持不变。功能仅面向本地、当前用户明确选择的目录，不上传文件。

## 待确认事项

App 菜单和菜单栏都有“待确认事项（N）…”入口。待确认事项不会强制弹窗，可在需要时手动处理；“查看最近分类结果”也可进入处理。

普通的“分类待确认”表示主题证据不足，并不一定已经提取到 DDL。可在窗口中补充主要内容、项目、截止日期和可选时间，点击“确认 DDL 并生成花朵”，也可切换为普通分类并选择核心提供的类别。候选有多条时逐项确认。

对图片 OCR 中 `dd|`、`dd1`、`ddI` 等疑似 `ddl` 的识别，核心会保留原文并标记为待核对候选；确认前不会生成花朵。明确识别的普通 DDL 沿用自动生成花朵的方式。未填写时间不会补成 23:59，过去日期也不会擅自改成下一年。

待确认记录保存在本机，重启后可继续处理；输入日期或时间无效时不会清除记录。确认完成后仍遵守用户设定的常驻 1–3 朵数量，多余按截止时间优先排队。

## 投喂与收获

- 同一次提取同时检查 DDL 和普通主题；成功分类增加葡萄，同时明确 DDL 可独立生成花朵。默认对有明确截止证据、完整有效日期的截图自动创建；不确定日期静默待确认。
- 花朵使用最新轻盈构图中的三株透明素材，固定在屏幕右下角，最多三朵；紧急任务优先可见，其余进入队列。
- 悬停展示主要内容、截止时间和项目；日期缺失年份会标注推定，未给时间则明确显示未注明。
- **双击花朵**即采摘并标记 DDL 完成，**无需确认弹窗**；单击与悬停只查看详情。交错剑光斩开花冠、像素花瓣碎片下落消失，动画结束后队列中的下一朵补位。超期不会自行删除 DDL；误操作可在“更多操作 → 撤销上次采摘”恢复。完成时间与队列保存在本机，重启后恢复；重复投喂不复活已完成项。
- 普通分类按核心的类别 ID 生长，一类一株，每个新增文件一颗葡萄。同一规范路径跨批次、重启后不会重复计数。
- 葡萄不再满 12 颗自动消失；更多像素果粒在同一串内缩放排布。没有杰瑞偷葡萄动画，也不会自动扣除葡萄。
- 花朵实心部分响应鼠标，透明空隙穿透桌面。可通过花朵或唤醒的葡萄区域拖入文件，也可从菜单选择文件。隐藏葡萄藤时已存在的花朵仍常驻。

项目目前取核心提供的网页标题、正文明确项目字段或分类名称/文件名作为来源；主要内容是通知原句摘录。核心仍使用规则识别明确日期，不支持“明天”“下周五”等相对日期。

## 2026-11-02：单朵常驻与安全移动

默认只显示一朵最临近截止日期的未完成任务花，其余在菜单的“DDL 任务列表”中保留。若所有任务都逾期，会展示其中一项，其余继续排队。左侧原有花位的上方第一片叶子下移一点，使花头到叶片之间的茎段更舒展。现有 v2 花头与叶片资源不变。

截图示例：`第四章作业` + `日程表：计算机网络` + `截止日期：2026/11/08 11:59 PM`，应自动得到 `计算机网络 · 第四章作业`，截止时间 `2026-11-08 23:59`，无需人工审批。OCR 可能将“日程表”误识为 `ABR`，后端在相邻两行明确属于同一作业卡片时仍能拾取课程名；有歧义时不强行拼接多个无关任务。

**重要：分类保存目录从旧版“复制”改为“移动”**。只要用户已设置目标文件夹、文件分类成功，便会将原路径文件移入分类子文件夹——这会改变 Finder 中的原位置。归档算法会先完整复制到同盘临时目标、流式核对 SHA-256、重命名并再次核对，之后才删除原路径；失败则不清理原件。没有选择目标文件夹时，只做分析与 DDL 提醒，不移动或删除文件。建议首次测试选取非重要图片，检查目标位置只有一张、来源按钮能打开归档后的图片。
